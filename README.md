# 冷库记录器帧校验器

纯前端页面（TypeScript + Vue 3 + Vite），用于校验冷库温度记录器导出的二进制文件。
文件只在浏览器内读取，**不上传、不访问任何外部服务**。

## 帧格式（固定 12 字节，多帧顺序拼接）

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 2 | 魔数，必须为 `A5 5A` |
| 2 | 1 | 版本，必须为 `01` |
| 3 | 1 | 标志位：bit0 高温、bit1 低温、bit2 低电量，bit3-7 必须为 0 |
| 4 | 4 | 小端无符号秒时间戳 |
| 8 | 2 | 小端有符号温度原始值，摄氏度 = 原始值 ÷ 10（固定一位小数） |
| 10 | 1 | 湿度，整数 0-100 |
| 11 | 1 | 序号 |

## 失败语义（不跳过坏数据）

文件长度不是 12 的倍数，或魔数、版本、保留位、湿度**首次**非法时：

- 解析立即停在**对应帧的字段首字节**，错误信息给出帧号与文件内绝对字节偏移；
- 之前已解析的合法帧保留并展示，但**整文件判定失败，禁止下载**；
- 完全合法时才按原顺序列出所有帧的字段与起始偏移，且可下载与表格一致的 JSON。

## 序号连续性（0-255 循环）

整文件解析成功后，按文件顺序对相邻帧做循环序号检查（首帧不参与比较，
255 → 0 视为连续；空文件与单帧文件按无断点处理）：

- 帧表上方给出结论：**未发现断点** 或 **存在断点**；
- 每个断点记录前后帧号、两侧序号、期望序号与后帧字节偏移，并在帧表中标记对应后帧；
- 下载的 JSON 内含与页面一致的连续性摘要及断点明细；
- 文件不合格时不执行检查，页面明确显示"未执行"，已保留的前置帧不作为完整批次结论。

## 告警片段归并（高温 / 低温 / 低电量）

整文件解析成功后，按文件顺序对三类标志（bit0 高温、bit1 低温、bit2 低电量）
**分别独立归并**，同一帧的多类告警可重叠存在：

- 某标志连续为真形成一个片段，遇到假值或文件结束即闭合；
- 相邻两帧即使标志都为真，只要循环序号不连续（存在断点）也在断点处切段，
  **绝不跨序号断点合并**（255 → 0 回绕不切）；
- 每个片段记录类型、起止帧号、起止字节偏移（末字节为结束偏移，含）、
  起止时间戳与包含帧数；
- 页面在连续性结论后展示告警摘要（各类片段计数）与片段表；
  点击片段可定位并高亮对应帧区间，再次点击取消，更换文件后定位自动清除；
- 三类标志全部为假时给出明确空态；
- 下载的 JSON 在 `alarms.summary` 与 `alarms.segments` 中包含与页面一致的
  摘要与片段明细；文件不合格时不分析（显示"未分析"），不依据已保留的
  合法帧前缀生成任何片段。

## 温度校准（复核用，不改写原始读数）

冷库探头定期校准后会产生统一温度偏移。整文件解析成功后，可在校准区
按 0.1 °C 步进输入 **-10.0 至 +10.0 °C** 的偏移并应用：

- 帧表并列显示**原始温度**与**校准温度**；湿度、序号连续性与告警等
  既有结论仍基于原始字段；
- 校准计算采用十分之一度整数相加（原始值与偏移同为 0.1 °C 整数），
  避免浮点漂移；应用后立即刷新全部校准温度；
- 超范围、非数字或小数位超过一位时在输入处反馈，生效值保留上次有效结果；
- 更换文件后继续使用当前偏移，输入框重新同步为当前生效值（上一批次
  未应用的输入不残留），重置则恢复零偏移；
- 文件不合格时禁止应用校准（与禁止下载一致）：保留帧的校准温度不应用
  偏移（与原始温度一致），重置入口保留，可将跨文件偏移恢复为零；
- 下载的 JSON 内含 `calibration` 校准说明（偏移量与计算方式）及逐帧
  `calibratedTemperatureRaw` / `calibratedTemperatureC`，与页面一致；
  原始字段、连续性与告警结构原样保留。

## 本地开发

```bash
npm install
npm run dev          # 开发服务器
npm run test         # Vitest 单元测试（字节序、负数、错误偏移）
npm run test:e2e     # Playwright 端到端（拖放、换文件、下载）
npm run build        # 构建到 dist/
npm run typecheck    # vue-tsc 类型检查
```

## Docker

```bash
# 启动页面，默认 http://localhost:8080
docker compose up web

# 覆盖宿主端口
WEB_PORT=9000 docker compose up web

# 一次性验收（单元测试 + 端到端测试，跑完即退出）
docker compose run --rm verify
```
